# Acceptance test coverage (A01–A38)

RFC 0001 §16 defines 38 acceptance scenarios. This page maps each id to the
source files that cite it, as input to RFC 0002 §12's completion tests.
`scripts/acceptance_coverage.py` generates the table; run it after adding or
renaming a citation. The scan is case-insensitive, so a test named
`a08_concurrent_reserves_cannot_overspend` counts as a citation of A08.

One caveat keeps this honest: a citation is a claim, not proof. Only the
cited test's assertions show whether the scenario is really covered, and an
uncited test may still cover a scenario.

## The ids with no reference, triaged

**Chain families without adapters (5).** A25 and A26 (Bitcoin), A27
(Cosmos), A28 (Sui) and A29 (Aptos) test adapters that do not exist yet.
They become reachable when RFC 0002 Gate E adds a chain, not before.

**Operational scope not built yet (3).** A32 (domain loss recovery), A33
(removed signer's residual authority) and A38 (attestation rejects an
unauthorized image) need the recovery and attestation machinery of RFC 0002
Gates C and D.

**Likely covered but uncited (1).** A35 (reconciliation discrepancy and
containment) looks exercised by the quarantine paths in
`services/reconciler/tests/money_loop.rs`, such as
`unknown_token_is_quarantined_and_differences_need_unique_admin_quorum`.
It needs one triage pass: confirm the assertions match the scenario and cite
the id there, or write the missing piece.
